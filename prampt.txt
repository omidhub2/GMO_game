# 10. GMO WALLET — CRITICAL FINANCIAL SYSTEM

The GMO wallet is one of the most important parts of the platform.

Implement three independent wallet accounts per user.

### Account 1: BALANCE

Purpose:

- Deposits.
- Purchases.
- Eligible payments.
- Tournament entry payments.
- Other approved spending operations.

### Account 2: REWARDS

Purpose:

- Daily mission rewards.
- Weekly mission rewards.
- Referral rewards.
- Promotional rewards.
- Achievements.
- Gifts.

### Account 3: PRIZE

Purpose:

- Tournament winnings.
- Competition prizes.
- Approved prize distributions.

Each account must have its own:

- Balance calculation.
- Transaction history.
- Incoming entries.
- Outgoing entries.
- Restrictions.
- Status.

The total GMO balance must be calculated from the three accounts.

Do not treat the three accounts as interchangeable.

### Spending policies

Implement configurable policies for:

- Which wallet account can be used for each operation.
- Spending priority.
- Whether transfers between accounts are allowed.
- Whether rewards can be used for tournament entry.
- Whether prizes can be withdrawn.
- Whether certain rewards are restricted.

These rules must be configurable by administrators.

### Ledger architecture

Use an immutable financial ledger.

Implement double-entry accounting.

Every financial transaction must create balanced ledger entries.

Do not directly modify wallet balances.

Balances must be derived from ledger entries or maintained through a rigorously synchronized projection that can always be reconstructed from the immutable ledger.

Use database transactions for all financial mutations.

Implement:

- Atomic operations.
- Idempotency keys.
- Concurrency protection.
- Row-level locking where necessary.
- Transaction reversals.
- Refunds.
- Reservations.
- Audit records.
- Reconciliation.

Never delete a completed financial transaction.

Corrections must be represented by reversal transactions.

### Tournament payment

When a user registers for a paid tournament:

1. Validate eligibility.
2. Validate tournament availability.
3. Validate wallet funds.
4. Reserve or debit funds atomically according to the tournament policy.
5. Prevent duplicate registrations.
6. Confirm registration only after successful financial processing.
7. Release reservations if registration fails or is cancelled.
8. Apply the configured refund policy.

### Prize distribution

Prize distribution must:

- Validate the final tournament results.
- Prevent duplicate prize payments.
- Use idempotency.
- Create ledger entries.
- Record prize references.
- Support administrator review.
- Maintain an audit trail.

Never distribute prizes based solely on an unverified client-side request.
